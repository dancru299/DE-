Học Docker giống như học lái xe: bạn không cần hiểu động cơ đốt trong, bạn cần biết chỗ cắm chìa khoá. Bài này dạy đúng phần đó — kèm ví dụ gõ được ngay.

01

"Máy tôi chạy được mà!"

Đây là câu nói kinh điển của dân lập trình. App chạy ngon lành trên máy bạn. Gửi cho đồng nghiệp — lỗi. Đẩy lên server — lỗi kiểu khác.

Lý do luôn giống nhau: mỗi máy một phiên bản Node/Python khác nhau, một bộ thư viện hệ thống khác nhau, một biến môi trường khác nhau. Code của bạn giống hệt, nhưng cái nền bên dưới thì không.

Docker giải quyết bằng một ý tưởng rất đơn giản:

Ý tưởng cốt lõi

Đóng gói app cùng với toàn bộ môi trường của nó vào một khối duy nhất. Đem khối đó chạy ở đâu cũng cho ra kết quả y hệt.

Hết. Mọi thứ còn lại trong bài này chỉ là cách làm ra cái khối đó và cách bật nó lên.

02

Vì sao gọi là "container"?

Ngày xưa hàng hoá lên tàu đủ hình dạng: bao gạo, thùng gỗ, kiện vải. Mỗi món phải bốc dỡ một kiểu, mất hàng tuần cho một chuyến tàu.

Rồi cả thế giới thống nhất một cỡ thùng thép tiêu chuẩn. Cần cẩu nào cũng nhấc được, tàu nào cũng chở được, xe tải nào cũng chở tiếp được — và không ai cần biết bên trong là gạo hay tivi.

Docker làm đúng điều đó với phần mềm. Bên trong container là Java, Python hay PHP không quan trọng. Bên ngoài, mọi container đều có cùng một bộ "tai móc" để Docker nhấc lên, đặt xuống, chuyển đi máy khác.

Bạn học một bộ lệnh, dùng được cho mọi loại app. Đó là toàn bộ giá trị của Docker.

03

Ba từ khoá bắt buộc phải nhớ

Docker có hàng trăm khái niệm. Người mới chỉ cần đúng ba từ này, phần còn lại suy ra được.

Image

Bản đóng gói · nằm im

Một khối chỉ-đọc chứa app + thư viện + hệ điều hành tối giản. Giống file cài đặt hoặc công thức nấu ăn. Nó không chạy, nó chỉ nằm đó.

Container

Bản đang chạy · sống

Là một image đã được bật lên. Giống món ăn đã nấu xong. Một image nấu ra được 10 container chạy song song, không đụng nhau.

Registry

Kho chứa · trên mạng

Nơi chứa image công khai, mặc định là Docker Hub. Giống siêu thị: bạn pull về dùng, hoặc push đồ của mình lên.

Mẹo nhớ

Image là danh từ nằm im. Container là động từ đang chạy. Nhầm hai cái này là nguồn gốc của 80% sự bối rối lúc mới học.

04

Khác máy ảo (VM) chỗ nào?

Câu hỏi này ai cũng hỏi, và câu trả lời ngắn hơn bạn tưởng.

Máy ảo mang theo nguyên một hệ điều hành đầy đủ. Nặng vài GB, khởi động mất vài chục giây, một máy chạy được chừng chục cái.

Container dùng chung nhân hệ điều hành của máy chủ, chỉ mang theo app và thư viện của nó. Nặng vài chục MB, bật trong một giây, một máy chạy được hàng trăm cái.

Bạn chỉ cần nhớ đến đây. Phần kỹ thuật bên dưới (namespace, cgroups) để dành cho lúc khác.

05

Chạy thử trong 60 giây

Mở terminal và gõ đúng một dòng này:

terminal
docker run -d -p 8080:80 --name web nginx

Mở trình duyệt vào http://localhost:8080 — bạn có một web server đang chạy.

Bạn vừa chạy nginx mà không hề cài nginx. Không tải file, không sửa config, không lo phiên bản. Máy bạn sạch y như trước.

Xem và dọn dẹp

terminal
# đang có gì chạy?
docker ps

# nó đang nói gì?
docker logs web

# chui vào bên trong container
docker exec -it web bash

# tắt và xoá sạch
docker stop web
docker rm web

Xoá xong là biến mất hoàn toàn, không để lại rác trên máy. Đây là lý do Docker rất hợp để thử nghiệm thoải mái: muốn thử PostgreSQL, Redis, MongoDB? Một dòng lệnh, chán thì xoá.

07

Tự đóng gói app của bạn

Đến đây bạn mới chỉ chạy đồ người khác làm sẵn. Giờ đóng gói app của chính mình bằng một file tên Dockerfile (không có đuôi mở rộng).

Giả sử bạn có một app Node.js đơn giản:

Dockerfile
FROM node:20-slim
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]

Đọc từng dòng như một công thức nấu ăn:

  • FROM — bắt đầu từ một cái nền có sẵn. Ở đây là Node 20 bản gọn. Không ai xây từ số 0.
  • WORKDIR — vào thư mục làm việc bên trong container, giống cd /app.
  • COPY package*.json — chép riêng file khai báo thư viện trước. Nghe lạ, nhưng cực kỳ quan trọng (xem mẹo bên dưới).
  • RUN npm install — cài thư viện, chạy lúc build.
  • COPY . . — giờ mới chép toàn bộ code vào.
  • EXPOSE — khai báo app lắng nghe cổng 3000. Mang tính ghi chú cho người đọc.
  • CMD — lệnh chạy khi container bật lên. Chỉ chạy lúc run, không phải lúc build.
Vì sao chép package.json trước?

Docker cache lại từng dòng. Nếu bạn chép hết code cùng lúc, sửa một dấu chấm phẩy cũng khiến npm install chạy lại từ đầu. Tách ra thì Docker biết thư viện chưa đổi và bỏ qua bước cài — build từ 2 phút xuống 3 giây.

Build rồi chạy

terminal
# đóng gói (dấu chấm = thư mục hiện tại)
docker build -t myapp:1.0 .

# bật lên
docker run -d -p 3000:3000 --name myapp myapp:1.0

Đừng quên tạo file .dockerignore cạnh Dockerfile, nếu không bạn sẽ chép cả node_modules và .git vào image:

.dockerignore
node_modules
.git
.env
*.log
08

Hai thứ người mới hay nhầm: -p và -v

-p là cái cửa

Container mặc định kín như một cái thùng — không ai bên ngoài vào được. Cờ -p đục một cái cửa.

ghi nhớ thứ tự
-p 8080:3000
   └┬─┘ └┬─┘
    │    └── cổng BÊN TRONG container
    └─────── cổng TRÊN MÁY BẠN
Mẹo nhớ

NGOÀI : TRONG. Bên trái là cái bạn gõ vào trình duyệt, bên phải là cái app đang lắng nghe. Nhầm thứ tự là lỗi phổ biến số một.

-v là cái ổ cứng ngoài

Container giống một tấm bảng trắng: xoá container là mất sạch mọi thứ đã ghi bên trong. Với database thì đó là thảm hoạ.

-v gắn một thư mục thật trên máy bạn vào bên trong container, nên dữ liệu sống sót qua mọi lần xoá:

terminal
docker run -d \
  -p 5432:5432 \
  -e POSTGRES_PASSWORD=matkhau123 \
  -v pgdata:/var/lib/postgresql/data \
  --name db postgres:16
Mẹo nhớ

Container là bảng trắng — xoá là sạch. Volume là quyển vở — giữ lại được.

09

Nhiều container cùng lúc: Compose

App thật hiếm khi chạy một mình — thường có web + database + cache. Gõ ba lệnh docker run dài dằng dặc mỗi sáng thì rất mệt.

Docker Compose cho phép mô tả tất cả trong một file docker-compose.yml:

docker-compose.yml
services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://postgres:matkhau123@db:5432/app
    depends_on:
      - db

  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: matkhau123
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:

Bật toàn bộ hệ thống bằng một lệnh, tắt cũng một lệnh:

terminal
docker compose up -d      # bật tất cả
docker compose logs -f     # xem log tất cả
docker compose down        # tắt và dọn
Chú ý dòng DATABASE_URL

Địa chỉ database là db — đúng bằng tên service. Compose tự tạo mạng riêng để các container gọi nhau bằng tên. Đây là mẹo cực kỳ tiện mà người mới thường không biết.

10

Năm lỗi người mới nào cũng dính

  1. Sửa code xong mà không thấy gì đổi. Image đã build là đông cứng. Phải docker build lại rồi chạy lại container. (Lúc dev, dùng -v mount code vào để khỏi build mỗi lần.)
  2. Gõ localhost trong container mà không kết nối được. Bên trong container, localhost là chính nó, không phải máy bạn. Muốn gọi container khác thì gọi bằng tên service.
  3. Mất sạch dữ liệu database. Quên -v. Xoá container là xoá luôn dữ liệu. Không có nút hoàn tác.
  4. Image nặng 1.5 GB. Dùng bản -slim hoặc -alpine, thêm .dockerignore, và tìm hiểu multi-stage build khi đã quen.
  5. Ổ cứng đầy sau vài tuần. Image cũ và container chết tích lại rất nhanh. Chạy docker system prune -a định kỳ.
11

Bài tập về nhà

Đọc mười lần không bằng gõ một lần. Làm ba việc này là bạn thật sự biết Docker:

  1. Chạy một postgres có volume, kết nối vào bằng công cụ DB quen thuộc, tạo một bảng. Xoá container rồi bật lại — kiểm tra bảng còn không.
  2. Viết Dockerfile cho một app nhỏ bạn từng làm. Build, chạy, mở được trên trình duyệt.
  3. Ghép hai thứ trên vào một docker-compose.yml. Chạy được bằng đúng một lệnh docker compose up.

Làm xong ba bài này, bạn đã vượt qua vạch xuất phát. Những thứ tiếp theo — multi-stage build, healthcheck, đưa image lên registry, rồi Kubernetes — sẽ dễ hiểu hơn nhiều khi bạn đã có nền tảng thực hành.
