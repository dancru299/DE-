🗺️ Cách đọc giao diện Airflow

Ảnh chụp thật từ Airflow trên máy bạn (DAG spark_ecommerce_pipeline). Số tròn 1 trên ảnh ứng với giải thích cùng số bên dưới. ⭐ = chỗ đáng quan tâm nhất.

1 · Màn hình DAGs (trang chủ) — tổng quan mọi pipeline

123456789
  1. 1Nút gạt — Xanh = scheduler TỰ chạy theo lịch. Xám = tạm dừng (chỉ chạy khi bấm tay). Tắt nhầm = pipeline chết thầm lặng.
  2. 2Tên DAG + tag — tên pipeline và nhãn phân loại (spark, hoc-tap).
  3. 3Runs ⭐ — chùm chấm lịch sử các LẦN CHẠY. Mỗi chấm = 1 lần chạy cả pipeline. Vòng xanh có số 3 = 3 lần chạy thành công. Nhìn có chấm ĐỎ không.
  4. 4Schedule — lịch tự chạy. @daily = mỗi ngày 1 lần.
  5. 5Last Run — lần chạy gần nhất lúc nào. Trễ so với lịch = có vấn đề.
  6. 6Recent Tasks ⭐ — chùm chấm trạng thái các TASK BÊN TRONG lần chạy mới nhất. 3 chấm xanh = cả 3 task OK. Đây KHÁC với cột Runs!
  7. 7Actions — ▶ chạy tay ngay · 🔄 xoá trạng thái để chạy lại · 🗑 xoá.
  8. 82 banner vàng — chỉ nhắc production nên dùng Postgres + executor mạnh. Học local thì kệ nó.
  9. 9Bộ lọc nhanh — Active/Paused/Running/Failed: liếc là biết có bao nhiêu DAG đang lỗi.

🔑 Chỗ dễ nhầm nhất: có HAI chùm chấm. Runs (số 3) = các LẦN CHẠY. Recent Tasks (số 6) = các TASK trong lần chạy gần nhất. Nếu Runs có 1 chấm đỏ và Recent Tasks có 2 xanh + 1 đỏ → lần chạy gần nhất hỏng, hỏng ở 1 trong 3 task.

2 · Grid — khung nhìn dùng nhiều nhất (mở mỗi sáng)

1234567
  1. 1LƯỚI Ô VUÔNG ⭐⭐ — trái tim của Grid. Mỗi HÀNG = 1 task, mỗi CỘT = 1 lần chạy (mới nhất bên phải). Mỗi ô tô MÀU theo trạng thái. Bấm 1 ô → panel phải hiện Logs.
  2. 2Tên các task — generate_data, run_spark_pipeline, check_output (đúng 3 task trong DAG của bạn).
  3. 3Cột Duration — cột càng cao = lần chạy đó càng lâu. Theo dõi để phát hiện pipeline chậm dần.
  4. 4BẢNG MÀU ⭐ — chú giải ý nghĩa mọi màu: success, failed, up_for_retry, running, skipped... Nhìn màu ô là biết sức khoẻ.
  5. 5Các tab — Details · Graph · Gantt · Code · Event Log · Run/Task Duration · Calendar. Đổi khung nhìn ở đây.
  6. 6Bảng tóm tắt (Details) — Total success 3/3, Mean Run Duration 40s, Max 55s, Min 10s, Total Tasks 3. Số liệu sức khoẻ tổng quát.
  7. 7▶ 🔄 🗑 — chạy tay / chạy lại / xoá, áp cho cả DAG.

🎨 Siêu năng lực của Grid: liếc qua lưới màu là biết ngay pipeline khoẻ hay bệnh, bệnh ở TASK nào, từ HÔM nào — không cần đọc log. Của bạn giờ toàn xanh = khoẻ mạnh.

3 · Graph — xem sơ đồ phụ thuộc giữa các task

1234
  1. 1Sơ đồ DAG ⭐ — 3 ô nối bằng mũi tên: generate_data → run_spark_pipeline → check_output. Đây chính là dòng a >> b >> c trong code, hiện thành hình. Pipeline 20-30 task thì khung này vô giá.
  2. 2Trạng thái mỗi node — mỗi ô ghi success + loại operator (BashOperator), theo lần chạy đang chọn.
  3. 3Chọn lần chạy — đang xem lần chạy 2026-08-03 12:06:14. Đổi lần chạy để xem màu node đổi theo.
  4. 4Layout — đổi hướng vẽ sơ đồ (Trái→Phải / Trên→Dưới).

Graph trả lời câu hỏi "cái gì phụ thuộc cái gì", còn Grid trả lời "lịch sử chạy ra sao". Hai khung bổ trợ nhau.

🎯 Mỗi sáng, dân DE chỉ nhìn 5 thứ này (theo thứ tự ưu tiên)

  1. Có ô ĐỎ nào không? (task failed) → việc số 1, bấm vào xem Logs, sửa ngay.
  2. Last Run có success và đúng giờ không? → tối qua pipeline có chạy không.
  3. Có task nào CAM lặp lại? (retry hoài) → dấu hiệu chập chờn, cần điều tra.
  4. Duration có phình bất thường? (tab Task Duration) → pipeline chậm dần (nhớ Bước 4!).
  5. Next Run có đúng lịch không? → scheduler còn sống không.
