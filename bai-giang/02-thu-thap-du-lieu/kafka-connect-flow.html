Luồng dữ liệu · CDC + Stream Processing

Kafka Connect × Redpanda Connect

Cùng một việc "di chuyển và biến đổi dữ liệu" mà bạn đã tự viết Python trong dự án shop — giờ được làm bằng cấu hình, không cần code. Đây là bản đồ luồng để hiểu trước khi bắt tay.

Hổ phách = thay đổi trong database (CDC) Cyan = dòng stream trong Kafka
01

Mỗi công cụ một việc

Streaming platform

Kafka

Đường ống trung tâm — nơi mọi dữ liệu chảy qua. Chính là thứ bạn đã học ở dự án shop.

Integration framework

Kafka Connect

Đưa dữ liệu vào / ra Kafka mà không cần viết code. Chỉ nộp một file cấu hình JSON.

Connector · Debezium

CDC

Bắt mọi thay đổi trong database (thêm/sửa/xoá) rồi đẩy vào Kafka — ngay lúc nó xảy ra.

Stream processing

Redpanda Connect

Đọc stream, lọc · biến đổi · định tuyến bằng YAML. Chính là Benthos đổi tên.

Điểm dễ nhầm: Kafka Connect rộng hơn CDC. Nó là cái khung; còn CDC chỉ là một ứng dụng cụ thể chạy trên khung đó, thực hiện bởi connector tên Debezium. Lead nói "Kafka Connect dùng để CDC" vì CDC là việc chính công ty bạn dùng nó.

04

Phần "ảo diệu": CDC đọc lén nhật ký

postgres · write-ahead log (WAL)
rsnapshot · orders#101 · {id, total, status}
cINSERT · orders#102 · after={total: 550000}
uUPDATE · orders#102 · status: NEW → PAID
cINSERT · orders#103 · after={total: 150000}
dDELETE · orders#101 · before={…}
↑ Debezium đọc từng dòng này, biến thành message Kafka

Database nào cũng có cuốn "nhật ký giao dịch" ghi lại mọi thay đổi trước khi áp vào bảng — Postgres gọi là WAL, MySQL gọi là binlog. Debezium đọc lén cuốn này. Trường op cho biết loại thao tác: create · update · delete · read.

  • ⚡

    Real-time

    Thay đổi vừa xảy ra là bắt được ngay — không phải hỏi dồn dập kiểu polling.

  • ✕

    Bắt được cả DELETE

    Điều mà cách chạy SELECT định kỳ không bao giờ thấy.

  • ≈

    Nhẹ cho database

    Chỉ đọc log, không quét bảng — gần như không tạo tải.

05

Redpanda Connect: input → pipeline → output

Mọi cấu hình đều có đúng ba phần. Đọc từ đâu, làm gì với dữ liệu, ghi đi đâu.

input

Đọc từ đâu

Kafka topic orders (event CDC thô). Cũng có thể là file, HTTP, hàng trăm nguồn khác.

pipeline · processors

Làm gì với dữ liệu

Lọc, đổi định dạng, thêm/bớt trường, tính toán — bằng ngôn ngữ map nhỏ tên Bloblang.

output

Ghi đi đâu

Topic orders.clean, hoặc Elasticsearch, DB phân tích, API… tuỳ đích cần.

# rút gọn event CDC dài dòng của Debezium còn vài trường cần thiết
input:
  kafka:
    topics: [ orders ]

pipeline:
  processors:
    - mapping: |
        # Bloblang: chỉ giữ id, khách, tiền, thao tác
        root.order_id = this.after.id
        root.khach    = this.after.customer
        root.tien     = this.after.total
        root.thao_tac = this.op          # c / u / d

output:
  kafka:
    topic: orders.clean

event thô nhiều chục dòng  →  4 trường gọn gàng cho hệ thống khác dùng
